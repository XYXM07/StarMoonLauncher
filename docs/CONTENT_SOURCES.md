# 内容来源

0.7.7 新增 ATLauncher、FTB、MC 百科和 GitHub 接入。

## 使用

在「下载 → 整合包」的来源下拉菜单选择 ATLauncher 或 FTB，再搜索、选择版本并安装。安装会创建独立实例；需要先在版本选择中创建或添加游戏文件夹。新实例的来源、项目与版本记录保存在实例元数据中。

也可以把本地 `.mrpack` 或 `.zip` 整合包拖入启动器主窗口，直接加入安装队列；支持多个文件，同一次拖入的重复路径只安装一次。拖到主窗口的输入框也会走安装流程，不会把路径写入设置。文件选择与拖拽共用同一导入流程，原始整合包文件始终保留。

在「下载 → 模组 / 整合包」选择 MC 百科，可以检索中文或英文条目并打开原站。检索使用社区维护的非官方服务，服务故障时保留「在MC百科搜索」按钮。它不是自动下载源，不会绕过原站验证码、下载限制或作者授权。

在「下载 → 模组」选择 GitHub，输入 `owner/repo` 或公开仓库链接，选择 Releases 中的 JAR 附件与目标实例。源码包、开发包及非 JAR 附件会过滤。安装会校验附件大小和可用的 SHA-256，读取 Fabric / Quilt / Forge / NeoForge 元数据，检查加载器、游戏版本及必需依赖。缺失前置时需另外安装；不执行下载的 JAR，不会猜测前置的下载仓库。

兼容性无法确认时默认停止，可在版本对话框主动选择允许未确认的兼容性。该选项不会放行已知的不兼容或缺少前置。更新同一仓库的已安装模组时保留禁用状态，并把旧文件移入实例回收目录；写入失败则恢复旧文件。GitHub 模组更新需回到下载页明确选择附件，不根据附件名自动推断更新版本。当前最多读取最近 100 个 Release，不支持私有仓库。

## 可选 AI 搜索与补下载

「设置 → 智能排查」提供两个独立开关，切换后即时保存；与诊断共用接口地址、模型和受 Windows DPAPI 保护的 API Key。GitHub 名称搜索默认关闭，整合包 AI 补下载默认开启。旧版配置升级时开启补下载一次，之后手动关闭会持续保留。

- **AI 搜索 GitHub 模组**：在 GitHub 来源输入中文或英文模组名称。模型整理百科关键词，启动器先检索 MC百科原站，再让模型从真实结果中选择对应条目，读取其「相关链接」并核实 GitHub 仓库。百科没有可用仓库时才继续查询 GitHub 公开索引。确认作者、Release 附件和目标实例后，使用原有 GitHub 安装流程。直接输入仓库链接不调用模型。
- **整合包下载失败时使用 AI 补下载**：Modrinth 整合包导入、ATLauncher、FTB、CurseForge 整合包在尝试清单中的原始地址后，仅对失败的 `mods/*.jar` 查找其他地址。先从 MC百科条目的 GitHub / Modrinth 相关项目链接取得候选文件，再以原文件 SHA-512 / SHA-1 查询 Modrinth；仍无候选时继续检索 GitHub。候选按百科来源优先提供给模型，下载地址必须是平台 API 实际返回的文件。

MC百科原站只读取公开搜索结果和条目相关链接，不执行脚本、不处理验证码、不镜像正文；原站不可用时可尝试已接入的社区 API，再继续其他平台。搜索最多读取前三页，把精确名称排在同名附属模组前；百科出站链接在本地解码，GitHub / Modrinth 项目仍由各自 API 核实。模型无法自行编造百科条目 ID 或下载网址。

### 补下载确认与版本选择

默认开启表示下载失败后可以进入补下载流程，每个失败文件仍需明确确认：

1. 原清单地址均失败后，弹出「整合包文件下载失败」，显示文件名和游戏 / 加载器版本。点击「使用 AI 查找版本」后才调用模型；取消安装或关闭窗口会停止本次整合包安装。
2. 查找完成后，显示「选择补下载版本」，列出真实发布版本、文件名、平台、已知游戏与加载器版本、发布日期和来源入口。不预选，即使只有一个候选也要手动选择并点击「下载所选版本」。
3. 仅下载所选文件，再校验原清单哈希和模组元数据。只有校验和文件提交均成功后才显示补下载成功。所选候选失败时显示具体原因，若还有候选则重新要求选择，不会自动尝试其他版本；全部失败时弹窗并清理本次新建的整合包实例。

窗口关闭、正在运行页面的取消按钮、同一批下载中其他文件的致命失败都会结束等待，避免安装任务一直阻塞。每次确认绑定当前任务和本次请求，旧窗口的响应不能继续其他文件。该选择界面用于补回原清单文件，不允许以其他版本替换而跳过原哈希。

补下载必须匹配整合包原清单提供的全部哈希与文件大小，并通过模组元数据读取后才提交。不会自动换成新版模组，不会执行下载文件。缺少有效原文件哈希、无法取得清单或 CurseForge 作者禁止第三方下载时不会强行补下载；没有匹配结果时按安装失败清理本次文件。配置文件与安装归档不进入 AI 搜索。模型自身无需支持联网；百科或平台不可用时会继续有界回退，最终仍可能需要手动下载。默认开启也需要先配置可用的模型接口和 API Key。

### 安装失败清理

本地导入、Modrinth / CurseForge 整合包安装、ATLauncher / FTB 安装共用一次安装会话。新建实例目录在创建时登记所有权，临时归档和文件放入本次会话的独立目录；失败或取消后清理这些目录，并恢复安装前的版本选择。已有实例、存档、原始整合包文件和其他游戏可复用的共享缓存不会删除。

安装失败后弹窗显示原始错误与清理结果；多个失败任务逐个提醒。Windows 短暂文件占用会有限重试；持续占用、目录所有权变化或路径检查不通过时不会扩大删除范围，会列出未能完成的清理步骤。目录删除前核实绝对路径、父目录与所有权标记，重试时保持同一个目录身份，Windows 目录联接不会导致其目标内容被删除。安装成功则保留新实例，仅移除临时文件和所有权标记。

发给模型的内容仅限模组名称、文件名、游戏与加载器版本和公开候选资料，不包含本地目标路径、账号令牌或存档。关闭两个新开关不会影响已有崩溃分析与启动前排查开关。模型请求有次数、响应大小和超时限制，同一时间只进行一个补下载搜索；其他正常文件继续并行下载。

## 安装行为

- ATLauncher 使用公开 v1 目录和官方 CDN 的 Configs.json / Configs.zip，解析加载器、客户端文件、配置、推荐可选项及其依赖。文件按清单验证 MD5 / SHA；配置归入新实例的游戏目录。
- FTB 使用当前官方 API，解析游戏与加载器目标、客户端文件及 SHA 校验。优先使用清单明确提供的 FTB 镜像，再尝试同一清单列出的其他地址；开启 AI 补下载后可继续查找匹配原文件的替代地址。服务端专用文件和标为 optional 的文件默认不安装。
- 文件下载复用现有多连接下载器，显示进度与速度。安装期间保持未完成标记，全部文件通过校验后才可启动；失败、取消或解压出错会清理本次新建实例和临时文件。
- 发布清单中内容完全相同的重复文件会合并；同一路径存在不同校验值时拒绝安装。所有下载与解压路径限定在新实例或本次任务的缓存内。
- 初次接入支持标准 Forge / NeoForge / Fabric / Quilt 目标。需要浏览器下载、额外 Java 库、自定义主类或其他特殊安装步骤的 ATLauncher 包会明确提示使用原平台安装，再添加已有游戏文件夹。

ATLauncher / FTB 不是所有上游文件的独立托管保证；若发布者没有给出可用地址，仍可能需要原平台授权或手动下载。MC 百科的条目资料与图片适用各自的许可，当前只提供简要检索结果及出处链接，不内置或镜像全文。

## 开发与验证

适配器在 `launcher/providers.py`，新实例安装流程在 `launcher/pack_install.py`。统一接入既有 content/search、content/versions 和 content/install 业务接口；来源与内容类型不匹配时拒绝调用，不回落到其他平台。

普通回归使用小型临时夹具，覆盖公开目录、分页、元数据、哈希、镜像、客户端筛选、路径越界、取消与原生界面。真实网络验收应单独运行，不加入 CI，不使用真实账号密钥，也不默认下载完整大型整合包。
