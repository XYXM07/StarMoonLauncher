# 模组、整合包、Java 与问题报告

以下功能自 0.7.8 起提供。

## 模组批量管理

入口：**版本设置 → 模组管理 → 批量管理**。原来的「检查更新」也会打开批量窗口并获取更新。

- 搜索、多选、全选可见项；可批量启用、禁用、删除、更新、锁定版本、解除锁定和忽略本次更新。
- 禁用或删除前显示依赖所选模组的其他模组，确认后执行。
- 更新列表展示当前版本和可用版本；提交时重新核对目标版本，避免安装预览之后出现的其他更新。
- 更新保留原有启用/禁用状态，包括原有前置模组。锁定的已登记模组不会被更新或作为自动前置更新覆盖。
- 「按文件哈希识别更新来源」将未登记文件的 SHA-512 发给 Modrinth，核对返回文件哈希、游戏版本和加载器后登记来源；不上传 JAR，也不根据文件名猜项目。识别失败的本地模组仍可批量启用、禁用和删除。
- Modrinth / CurseForge 来源可检查更新；CurseForge 仍需 API Key。GitHub 附件继续在下载页明确选择，不自动猜测附件。
- 忽略更新仅跳过当前发现的版本；更高版本仍会提示。可在「变更记录」恢复忽略或锁定操作。

批量操作前备份受影响的文件及登记信息；下载失败、校验失败或取消时恢复。涉及递归前置下载的更新会备份整个模组目录；单纯锁定和忽略更新只备份元数据。

## 整合包原地升级

入口：**版本设置 → 概览 → 升级整合包**。支持 Modrinth、CurseForge、ATLauncher、FTB。

1. 新安装的在线整合包自动保存来源及原始文件清单。
2. 旧整合包缺少来源记录时，填写平台和项目 ID（Modrinth 也可填写项目 slug），获取版本列表，选中原版本并点击「将列表所选设为当前版本」，再选择目标版本。没有原始清单时会下载旧包重建清单。
3. 下载和安装在私有临时版本中完成，共享原版及支持库缓存，不替换当前实例。待所有下载成功后显示新增、替换、删除文件和本地修改冲突。
4. 「保留本地修改」跳过冲突；「采用整合包文件」应用冲突项。确认窗口同时显示目标 Minecraft 和加载器。
5. 保持原实例 ID、名称、启动参数；更新游戏/加载器配置并保存恢复备份。失败或取消时保留原文件。

升级排除 `saves`、`screenshots`、`logs`、`crash-reports`、`backups`、`options.txt`、`optionsof.txt` 和服务器列表。玩家添加且未与新包发生路径或已识别模组 ID 冲突的文件保持原样。可识别的模组更换文件名后也会保留禁用状态；未知元数据不能可靠判断模组改名。

当前升级面向启动器管理的独立整合包实例；外部 `.minecraft` 版本需要先导出并导入为独立实例。保留本地修改可能仍需要玩家调整配置或模组版本，不意味着保证所有整合包组合可以启动。

## 依赖关系与修复

入口：**版本设置 → 模组管理 → 依赖关系与修复**。无需模型 API。

树形列表显示模组和其必需依赖、声明的不兼容关系、要求范围、当前版本及状态。复用 Fabric / Quilt / Forge / NeoForge 的本地元数据解析，识别禁用模组、嵌套模组和提供的别名。无法解释的版本表达式标记「无法确认」。

扫描先匹配实例加载器，再读取对应元数据；多加载器 JAR 不混用其他加载器的依赖。Quilt 可读取 Fabric 元数据，旧版 NeoForge 保留 `mods.toml` 支持。没有匹配元数据的模组会提示核对加载器版本，不推荐为它安装其他加载器的前置。

- 已安装但禁用的前置可直接启用并验证。
- 缺失或版本不符时，可在 Modrinth / CurseForge 搜索候选，再选择具体项目和兼容发布版本。
- 安装后重新核对实际模组 ID、版本范围和新增依赖问题。可识别的单模组旧 JAR 可以被所选新版本替换；包含多个模组 ID 的文件不自动拆除。
- ID 或版本未满足、出现新依赖问题时恢复原文件。模组加载器的所有动态冲突并不能由静态元数据发现。

## Java 管理中心

入口：**设置 → 游戏 → Java 管理中心**，以及 **版本设置 → 设置 → Java 管理中心**。

显示检测到的 Java 版本、PE 架构、路径、托管目录占用空间以及直接引用它的版本。支持下载 Eclipse Temurin Java 8 / 11 / 17 / 21 / 25，并选择 x64 / x86 / ARM64（以官方提供的构建为准）。下载按官方 SHA-256 校验，解压后实际执行 `java -version` 验证。

可设为全局默认，或应用到当前游戏版本。全局自动匹配逻辑继续保留。清理只处理未被全局设置、版本路径或已检测路径引用的托管 Java，将其移入 `data/trash/`；不删除系统 Java。游戏运行期间不执行 Java 清理。

## 日志与问题报告中心

入口：**版本设置 → 日志**。

- 选择独立启动日志、加载器安装日志、游戏日志和崩溃报告。
- 自动刷新、搜索、WARN 及以上 / ERROR 和 FATAL 筛选，定位当前显示内容中的首个错误。
- 每个日志最多显示末尾 1 MB；保留用户阅读时的滚动位置。
- 「导出问题报告」生成本地 ZIP，包含精简运行环境、模组元数据、依赖检查结果和最近最多 8 个日志的末尾内容。
- 复用令牌、密钥、账号、常见个人路径、URL/IP 等脱敏，不包含账号配置、存档或截图，不自动上传。分享前可自行检查 ZIP 内容。

## 变更恢复

入口：**版本设置 → 概览 → 变更记录**。备份保存在实例目录下的 `changes/`。

可恢复批量操作、依赖修复、来源识别和整合包升级。只处理对应变更记录的文件；若之后又被修改则拒绝覆盖，需先处理后续变更。游戏运行期间禁止恢复。升级后产生的游玩时间、版本重命名等无关字段不会因恢复而丢失。

写入前保存恢复记录，中断后可在变更记录中恢复尚未完成的操作。恢复开始后不响应取消，防止只恢复一半；备份不会自动清理。

## 验证

定向检查位于 `tests/test_management.py`、`tests/test_management_native.py`。相关日志保存在忽略目录 `test-results/management-targeted.log`。

可选真实网络验证：

```powershell
python tests/integration_management.py --download-java
```

此命令读取官方目录、校验 Modrinth SHA-512 查询，使用隔离临时目录下载并运行 Java，随后清理临时运行时；不启动 Minecraft、不修改已有版本。普通本地构建不运行全量回归。
